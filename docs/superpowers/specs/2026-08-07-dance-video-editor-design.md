# 多人频剪辑软件（Vibe Dance Editor）设计文档

> 日期：2026-08-07
> 状态：已评审
> 目标：桌面客户端软件（macOS + Windows），从多人视频中框选目标人物，自动跟踪并输出以该人物为中心的裁剪视频。

## 1. 背景与目标

多人跳舞场景的视频中通常有多人入镜，用户希望：

- 选中某一个人；
- 自动跟踪这个人全程舞蹈；
- 输出一段以这个人为主、动态跟随裁切、去掉周围人的视频。

**MVP 明确不做**（YAGNI）：
- 不做人像抠图（matting），只做跟随框裁剪（tracking + crop）；
- 不做手持/运镜画面（运动补偿），只支持单机位固定拍摄；
- 不做手机相册/短视频平台导入，只支持本地视频文件；
- 不做手动选起止时间，默认全程自动跟；
- 不做多目标同时导出。

## 2. 产品交互与行为

1. **导入**：用户导入本地视频文件（mp4 / mov）。
2. **预览**：应用内播放视频，支持播放/暂停。MVP 不做时间线拖动选帧（框选在首帧完成即可），此能力列为后续增强。
3. **框选**：在预览画面上用 9:16 取景框框住目标人物（详见 §2.1），框选完成后自动开始全程跟踪。
4. **进度**：跟踪/导出过程展示实时进度百分比，可取消。
5. **导出**：输出以目标人物为中心的裁剪视频到用户指定路径。

### 2.1 框选交互设计

**核心原则：框选框宽高比锁定为输出比例（9:16），所见即所得** —— 用户框住的就是最终输出的画面。

```
┌─────────────────────────────┐
│   视频预览画面               │
│                             │
│   ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒   │ ← 框外半透明暗化遮罩
│   ▒▒ ┌───────────────┐ ▒▒  │
│   ▒▒ │  9:16 取景框   │ ▒▒  │   锁死比例，等比缩放
│   ▒▒ │   目标人物     │ ▒▒  │   拖动=移动，拖角=缩放
│   ▒▒ └───────────────┘ ▒▒  │
│   ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒   │
│                             │
│   [开始跟踪]  [输出: 1080×1920 ▾] │
└─────────────────────────────┘
```

**流程：**
1. 打开视频，画面中央默认出现 9:16 取景框，框外暗化遮罩。
2. 用户**拖动**取景框到目标人物身上，拖**边缘或角**等比缩放（始终锁 9:16，图片编辑器式光标反馈：角=斜向箭头，边=横向/纵向箭头）。
3. 输出分辨率可选：默认 **1080×1920**（竖屏），预设 720×1280 / 1080×1920，支持自定义宽高。
4. 点「开始跟踪」→ 先选择保存位置 → 引擎把第一帧取景框的位置和尺寸作为**固定输出框**。
5. 导出完成后可一键「打开所在文件夹」。导出视频**保留原视频音轨**。

**取景框大小策略：固定大小**（经用户确认）。
- 人物走近 → 构图过满甚至出框；人物走远 → 人物变小、输出被放大、画质略降。
- 缓解建议：框选时把取景框调大，覆盖人物主要活动范围；输出分辨率调低可减轻画质损失。

### 遮挡处理
目标人物被其他人完全遮挡时，跟踪器通过「帧间跟踪 + 定期检测重定位」自动续跟，用户无感；仅在长时间（超过阈值）彻底丢失时回退到最后可信位置并在 UI 提示。

### 性能预期
- 目标硬件不明确：**CPU 优先**，跟踪引擎在无 GPU 的常规电脑上可运行；有 GPU（NVIDIA / Apple Silicon）时自动加速（YOLO 检测部分）。

## 3. 架构总览

```
┌─────────────────────────────────────────────┐
│              Electron 桌面壳 (UI 层)          │
│  React/Vite + 视频预览 + 框选交互 + 进度条    │
└──────────────┬──────────────────────────────┘
               │ HTTP/WebSocket (localhost) 或 stdio JSON
┌──────────────▼──────────────────────────────┐
│            Python 处理引擎 (算法层)           │
│  FFmpeg 解码 → 跟踪 → 裁剪框平滑 → 编码      │
│  任务队列 + 进度回传                         │
└─────────────────────────────────────────────┘
```

选型结论：**Electron + React（UI 层）+ Python（处理引擎）**，通过本地进程间通信（HTTP/WebSocket 或 stdio JSON）协作。

- 选择 Electron 的理由：UI 现代美观、前后端解耦便于测试演进、生态成熟。
- 选择 Python 的理由：OpenCV / ultralytics YOLO 等 CV 生态最成熟，算法开发迭代快。

## 4. 组件划分

| 单元 | 职责 | 关键依赖 | 接口 |
|---|---|---|---|
| **UI 层 (Electron + React)** | 导入、视频预览、canvas 框选、进度显示、导出按钮 | React, Vite, Electron | 调用 Task API |
| **Task API** | UI ↔ 引擎的通信契约：启动任务 / 进度回调 / 取消 | 轻量 HTTP/WS 或 stdio JSON | 见 §6 |
| **跟踪引擎 (Python)** | 逐帧解码 → 目标跟踪 → bbox 平滑 → 编码输出；纯算法核心，不依赖 UI | OpenCV, ultralytics YOLO, FFmpeg | 实现 Task API |
| **打包器** | 生成 macOS .dmg / Windows .exe，内嵌 Python 运行时 | electron-builder + PyInstaller | 无（构建产物） |

## 5. 核心数据流（一次导出）

1. **导入**：用户选 mp4 → 记录文件路径，UI 用 `<video>` 标签预览。
2. **框选**：预览画面用 9:16 取景框框住目标 → 前端拿到 `(x, y, w, h) + 帧号 + 输出分辨率`（画布坐标换算为视频原始分辨率坐标，w:h 恒为 9:16）传给引擎。
3. **跟踪**：引擎从该帧起，CSRT/KCF 单目标跟踪器逐帧跟踪；每 N 帧（默认 30）跑一次 YOLOv8n 人体检测，取与当前框 IoU 最高的检测结果重定位。输出每帧人物 bbox。
4. **平滑**：对人物 bbox 序列做 Kalman + 指数移动平均平滑，消除快速动作导致的框抖动。
5. **渲染**：输出框固定尺寸（第一帧取景框的 w/h，锁 9:16）、中心对齐平滑后的人物 bbox 中心、clamp 到视频边界 → 从原视频裁出该区域 → 缩放到输出分辨率 → FFmpeg 编码输出。
6. **进度**：引擎逐段回传进度百分比；支持取消（终止任务并丢弃未完成输出）。

## 6. Task API（通信契约）

- `POST /task`：提交任务 `{ video_path, init_frame, bbox, output_size, output_path, params }`。其中 `bbox` 为 9:16 取景框（w:h 恒为 9:16），`output_size` 为 `{ width, height }`（默认 `{ 1080, 1920 }`）。
- `GET /task/{id}`：轮询任务状态，回传 `{ task_id, progress, status, message }`。
- `POST /task/{id}/cancel`：取消任务。

任务状态机：`QUEUED → RUNNING → DONE | FAILED | CANCELLED`。

参数 `params`（含默认值）：
- `tracker_type`：`CSRT`（精度优先，CPU 慢）或 `KCF`（速度优先）。
- `redetect_interval`：重定位检测间隔帧数，默认 30。
- `smooth_window`：平滑窗口长度，默认 10 帧。
- `lose_threshold`：跟踪丢失判定阈值（连续丢失帧数），默认 30。

## 7. 关键技术细节

- **框选交互**：前端在 `<video>` 上用 canvas overlay 画 9:16 取景框，框外半透明暗化；拖动移动、拖角等比缩放；坐标按视频原始分辨率换算。
- **跟踪器选择**：CSRT（精度优先）/ KCF（速度优先），做成设置项。
- **重定位策略**：`t0` 用检测器初始化 → 帧间单目标跟踪 → 每 N 帧 YOLO 检测取 IoU 最高者校准。
- **bbox 平滑**：Kalman + 指数移动平均。
- **输出框**：固定尺寸（第一帧取景框的 w/h，锁 9:16），中心对齐平滑后人物 bbox 中心，clamp 到视频边界。
- **输出尺寸**：`output_size` 默认 `{ 1080, 1920 }`（竖屏 9:16），预设 720×1280 / 1080×1920，支持自定义宽高；宽高需为偶数以满足编码器。

## 8. 错误处理

- 跟踪完全丢失（超过 `lose_threshold`）→ 回退到最后可信位置，UI 提示。
- 帧解码失败 → 跳过该帧，记录日志。
- 导出中断 / 取消 → 丢弃已编码部分，保证输出文件完整。

## 9. 测试策略

- **跟踪引擎单元测试**：合成视频（静态背景 + 移动方块），验证 bbox 跟随、遮挡续跟、平滑不抖动。
- **UI 测试**：React 组件测试（框选交互、输出尺寸选择、进度轮询）。
- **集成验收**：引擎端到端冒烟脚本 + 用一段真实舞蹈视频做手动端到端验收。

> MVP 不引入 Playwright E2E（桌面 Electron 应用配置成本高，组件测试 + 引擎集成测试已覆盖核心路径），列为后续增强。

## 10. 里程碑（后续由 writing-plans 细化）

1. 项目脚手架（Electron + React + Python 引擎骨架、IPC 打通）。
